# 完整更新日志规则

`CHANGELOG.md` 是 MoonSprite 的长期更新账本。从本规则生效后，所有完成的软件变化都必须保留，不能只在发布时用少量摘要代替。

## 记录范围

以下变化必须记录：

- 新功能和已有功能扩展。
- Bug 修复、兼容性修复和异常保护。
- 用户交互、界面、快捷键、默认值和文案变化。
- 性能优化及已确认的性能退化。
- 不改变外部行为但影响后续维护的重构。
- 依赖、构建、CI、安装、文件关联和平台集成变化。

只修改说明文字、补充代码注释或修正测试描述且不改变软件、构建和维护行为时，可以不增加条目。失败尝试、临时调试、生成目录和未采用方案不进入更新日志。

## 编写方式

1. 每个可独立说明的变化使用一条项目符号，不把多个无关功能或 Bug 合并成“若干优化”。
2. 新记录始终写入文件顶部的 `## 未发布`，并按“新增功能”“交互改进”“问题修复”“性能优化”“工程维护”等类别归档。
3. 条目说明用户或维护者实际得到的结果，必要时写明快捷键、默认值、兼容范围或迁移行为。
4. 同一问题多次修正时保留最终有效结论；已经发布的事实不得删除。事实描述错误时可以更正，但应在提交说明中注明原因。
5. 发布时把“未发布”中的全部条目原样移动到目标版本，并立即重新建立空的 `## 未发布`。禁止为了缩短文件而合并或丢弃条目。
6. 历史版本永久保留在 `CHANGELOG.md`；文件过长时允许增加索引，但不把旧版本移出仓库。

## 自动门禁

`pnpm check:maintenance` 会运行 `scripts/check-changelog-update.mjs`：

- 本地开发时检查当前工作树中的软件变化。
- Pull Request 中比较目标分支与当前分支。
- 推送到 `main` 后比较推送前后的提交。
- 检测到源码、平台代码、构建配置、工作流或维护脚本变化，而 `CHANGELOG.md` 没有同步变化时，检查失败。

自动门禁只能确认“更新日志发生了变化”，无法判断文字是否完整。开发者和 AI 在任务结束前仍必须逐项对照实际改动，确保没有漏记。
