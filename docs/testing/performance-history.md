# 性能更新记录

本表记录每次运行时代码更新后的性能结果。它回答“这次更新比上一次快了还是慢了”，具体测试输入、阈值和测量方法仍以 [性能基线](performance-baseline.md) 为准。

## 记录规则

1. 每次包含运行时代码的提交或交付都必须增加一条记录；纯文档、注释或格式修改也要登记为“免测”。
2. 同一自动基准连续运行三次，记录三次平均耗时的中位数。
3. 使用相同开发机、固定输入、固定随机种子，并记录对应代码提交。
4. 相比最近有效记录退化超过 5% 标记为“关注”，超过 25% 标记为“阻止合并”，完成原因分析或修复后才能继续性能敏感改动。
5. 没有自动基准覆盖的交互必须明确写“未覆盖”，禁止用主观流畅度代替数据。
6. 性能优化不能改变像素结果、快捷键、撤销语义或文件兼容性。

## 尚未覆盖

以下项目在补齐自动测量前，每次更新都应在结论中标记“未覆盖”：

- 镜像视图后的平移、缩放和笔刷预览。
- 大尺寸程序纹理笔刷连续绘制。
- 调色盘三角区域和色轮连续拖动。
- 多图层、混合模式和透明度下的合成耗时。
- 空白工程、512 × 512 多图层工程和长时间编辑后的内存占用。
- Windows WebView2 实机的帧时间、React 提交耗时和 GPU 合成时间。

## 目标阈值

| 指标 | 目标 |
| --- | ---: |
| 平移、缩放和连续绘制帧时间 `p95` | ≤ 16.7 ms |
| 超过 25 ms 的卡顿帧比例 | < 1% |
| 单次主线程阻塞 | < 50 ms |
| 512 × 512 魔棒连续区域相对同机基线退化 | ≤ 5% |
| 复杂选区边界相对同机基线退化 | ≤ 5% |

| 单次更新主入口 gzip 体积增长 | ≤ 5% |
