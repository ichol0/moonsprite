# 性能基线

性能目标是保持像素编辑、画布移动和缩放的连续反馈。基准数据用于发现退化，不用于跨硬件比较绝对成绩。

每次更新的实际结果统一记录在 [性能更新记录](performance-history.md)。本文件只定义固定场景、测量方式和阈值。

## 性能影响分级

P0-P4 只用于已经明确进入性能审计的任务，不是普通需求或普通 `dev.X` 发布的日常门禁。只有大版本或阶段里程碑、性能专项、已观察到明显退化或用户明确要求时，才运行 `pnpm check:performance-scope -- <自上次基线以来的相关文件...>` 获得建议等级。脚本只能辅助选择场景；涉及更大范围、循环复杂度、内存分配或高频订阅时必须人工上调等级。

| 等级 | 典型范围 | 必须验证 | 性能历史 |
| --- | --- | --- | --- |
| P0 | 文档、注释、测试、维护脚本 | 无性能基准 | 不登记 |
| P1 | 普通弹窗、菜单、快捷键、文件规则、低频状态 | 类型检查和相关功能测试 | 不登记 |
| P2 | 选区算法、画布输入、调色盘拖动、局部图层操作 | 一个代表尺寸和相关场景，或对应算法基准 | 记录相关指标 |
| P3 | Canvas 渲染、像素算法、合成缓存、Zustand 高频订阅 | 完整画布基准一次 | 记录完整结果 |
| P4 | 关键依赖升级、大规模重构、性能基线调整、大版本里程碑 | 完整画布基准三次取中位数、算法基准和 Windows 桌面验证 | 记录中位数与实机结论 |

性能影响无法确定时按较高一级处理。Bug 修复若只改变正确性且不进入高频路径，可按 P1；同一任务包含多个等级时采用最高等级。

### 画布交互

运行：

```powershell
pnpm bench:canvas -- --size=512 --scenario=pan,zoom
pnpm bench:canvas -- --full
```

支持尺寸 `128`、`512`、`1024`，支持场景 `pan`、`zoom`、`rotated-zoom`、`draw`。不传筛选参数时为兼容旧流程仍运行全部场景；P3/P4 应显式使用 `--full`，P2 必须只选择与改动相关的尺寸和场景。

基准会先执行正式 Web 构建，再使用本机 Chrome 或 Edge、1280 × 800 视口和固定手势，分别测量 128 × 128、512 × 512、1024 × 1024 画布的平移、缩放、旋转后缩放和连续绘制。输出包括：

- `p50`、`p95`、`p99` 帧间隔和超过 25 ms 的比例。
- Canvas 主绘制的 `p95` 与最长耗时。
- 指针处理函数的 `p95` 与最长耗时。
- `PerformanceObserver` 捕获的最长主线程任务。

Headless Chromium 的 `requestAnimationFrame` 不锁定为 60 Hz，因此帧间隔只用于同机相对比较；主绘制和指针处理耗时可用于定位代码热点。正式体验仍需在 Windows WebView2 中手动复核。

2026-08-02 三次运行中位数：

| 画布 | 场景 | 帧 `p95` | >25 ms | 主绘制 `p95` | 指针处理 `p95` | 最坏帧 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 128 × 128 | 平移 | 3.70 ms | 0.307% | 0.30 ms | 0.20 ms | 117.9 ms |
| 128 × 128 | 连续绘制 | 3.70 ms | 0.286% | 0.90 ms | 0.40 ms | 99.9 ms |
| 512 × 512 | 平移 | 3.70 ms | 0.327% | 0.30 ms | 0.20 ms | 96.4 ms |
| 512 × 512 | 连续绘制 | 3.70 ms | 0.284% | 1.20 ms | 0.40 ms | 117.9 ms |
| 1024 × 1024 | 平移 | 3.70 ms | 0.316% | 0.30 ms | 0.20 ms | 103.6 ms |
| 1024 × 1024 | 缩放 | 3.70 ms | 0.640% | 0.40 ms | 0.20 ms | 35.7 ms |
| 1024 × 1024 | 旋转后缩放 | 3.70 ms | 0.213% | 0.50 ms | 0.20 ms | 29.0 ms |
| 1024 × 1024 | 连续绘制 | 3.70 ms | 0.285% | 1.10 ms | 0.40 ms | 121.4 ms |

主绘制和指针函数都明显低于 16.7 ms，但操作提交后曾存在约 96-121 ms 的异步长任务。2026-08-02 增加按区域记录的 React Profiler 后，先收窄停靠栏目的刷新边界，再拆分应用外壳。当前 1024 × 1024 连续绘制的 React 提交 `p95` 中位数为 8.6 ms，最长任务为 59 ms；旋转后缩放的 React 提交 `p95` 为 1.3 ms。剩余长任务主要出现在连续绘制提交后的作品预览和运行环境调度，不在 Canvas 主绘制函数内。

React Profiler 仅在基准 URL 带有 `?moonsprite-perf=1` 时启用，普通软件运行不承担测量开销。基准输出中的 `reactCommitP95`、`longestReactCommit` 和 `reactByRegion` 用于判断组件提交范围；它们只适合同机、同构建方式前后比较。

## 待扩展基准

- 复杂魔棒选区的蚂蚁线缓存与更新。
- 大尺寸程序纹理笔刷连续绘制。

- 多图层合成、混合模式和透明度变化。
- Windows WebView2 实机的 60 Hz/120 Hz 帧时间和 React 提交耗时。

## 测量规则

- 使用固定输入数据和随机种子。
- 分开测量算法耗时、Canvas 重绘和完整指针事件延迟。
- 性能优化不得改变像素结果或交互契约。
- 每次修改基准输入、阈值或测量方式时记录原因和日期。
- P0/P1 不运行性能基准且不登记；P2-P4、明确性能优化、退化分析和基线调整才追加性能历史。
