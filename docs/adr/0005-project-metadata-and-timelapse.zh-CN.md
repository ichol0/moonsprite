# ADR-0005：项目元数据与缩时快照

中文 | [English](0005-project-metadata-and-timelapse.md)

## 状态

已接受

## 背景

重新打开工程后，网格可见性必须继续跟随对应工程，而缩放和平移等导航状态必须仅存在于会话中。工程统计与缩时录制也需要在保存和恢复后保留，但不能进入文档撤销栈。记录原始指针事件会让回放依赖工具实现细节；保存原始尺寸的完整快照则会让工程体积失去实际上限。

## 决策

- 仅将像素网格可见性、自定义网格可见性和自定义网格几何作为工程显示元数据持久化。缩放、平移、旋转和镜像保留在会话中。
- 持久化已提交操作数、绘制笔划数和活动绘制时长的规范化计数器。
- 启用缩时录制时，在文档操作提交边界捕获一张合成 PNG。视图操作和栏目操作不触发捕获。
- 将缩时 PNG 文件保存在 `timelapse/` 下，并在清单中保存其元数据。活动快照列表最多保留 600 项；达到上限时对较旧项降采样。
- 通过 Renderer 的 `MediaRecorder` 支持将记录的快照导出为真实视频。MP4 与 WebM 独立提供；编码前使用 `MediaRecorder.isTypeSupported()` 检查所选容器。若运行环境不能提供请求的编码器，则显示明确错误，不生成扩展名与内容不匹配的文件。

## 结果

网格选择可以按工程保存，同时不会序列化临时导航状态。缩时录制只在明确启用时增加 CPU 工作和工程体积。基于快照的录制不依赖撤销内部结构和未来工具实现，但无法重建两次已提交编辑之间的中间指针移动。

## 替代方案

拒绝持久化每个指针事件，因为回放会依赖工具版本和选区状态。也拒绝持久化完整撤销条目，因为撤销数据不是稳定文件格式，并且可能缺少正向回放所需的信息。
